# Importing transactions

Almost every bank lets you download your transactions as a CSV file or an Excel workbook from
its website (look for "Download", "Export" or "Statements"), and most European banks also offer
**CAMT.053** bank statements (XML files). FlyBudget can import all of them into any account. It's
free, works with every bank, and nothing but the file is involved. If you'd rather have
transactions arrive by themselves, [connect a bank](./bank-sync) instead.

## Importing a file

1. Open the account the transactions belong to, and choose **Import CSV**.
2. Drop the file on the window, or click to pick it. A CAMT.053 statement goes straight to the
   preview (step 4): there are no columns to map.
3. **Map the columns.** FlyBudget reads the file's headers and guesses what each column holds.
   It knows common header names in English and several European languages, including Spanish,
   however they're capitalized or accented. When two columns look like the same thing, only the
   first is guessed as that; the others are set to **Skip**. On a card statement with
   instalments, the instalment column (`Imp. cuota`) is the amount and the purchase's total is
   skipped, so each statement adds only that month's instalment.
   Check the guesses, and change any that are wrong: **Date**, **Payee**, **Amount**,
   **Inflow**, **Outflow**, **Direction (in/out)**, **Notes**, **Currency** or **Skip**. The first rows are shown underneath so you
   can see that it looks right. You need a date and either an amount or inflow/outflow columns.

   <Screenshot name="import-csv" alt="Mapping the columns of a CSV file" dialog />

4. **Preview.** Every row is listed with its date, payee and amount. Rows you already have are
   marked **duplicate** and unticked. Untick anything else you don't want. Rows FlyBudget can't
   import (a date, amount or direction it can't read, or an amount of zero) are listed above the preview by
   row number, so you can fix the file first.

   <Screenshot name="import-csv-preview" alt="The preview before importing" dialog />

5. Choose **Import**. FlyBudget says how many transactions it imported and how many it skipped.

FlyBudget remembers how each account's files look: the separator, encoding, rows above the
header, column mapping, date and amount formats, and your word for money going out. The next
time you import a file with the same columns into that account, it uses them again, so you only
answer its questions once. (If a file clearly says otherwise, for example a date with a day above
12, the file wins.)

Your [rules](./rules) run on every imported transaction, so they can rename
`SQ *DAILY GRIND 1142` to _Daily Grind Coffee_ and put it in _Coffee Shops_. FlyBudget keeps the
bank's original text as the **imported description**, which rules can match on too.

## Duplicates

FlyBudget remembers every row it imports, so importing a file that overlaps one you imported
before is safe: the rows you already have are skipped. Two identical rows in the same file (two
coffees at the same price on the same day) are treated as two purchases.

Transactions you entered by hand aren't matched against an import. If you enter transactions by
hand _and_ import files for the same account, check the preview for rows you already have.

If you imported files from a European bank before FlyBudget understood day-first dates and decimal
commas, those transactions may have the wrong date or amount. Importing the same file again won't
recognize them as duplicates, because their dates and amounts no longer match the file. Delete the
wrong transactions first, then import the file again.

## What FlyBudget understands

- **Separators**: commas, semicolons (common in Europe, where the comma is the decimal
  separator) and tabs. FlyBudget picks the one in the file's header row; change it under
  **Separator** if the columns look wrong.
- **Account details above the table**: some banks (DKB and Comdirect, for example) start the
  file with a few lines about the account. FlyBudget finds the header under them by itself and
  shows how many rows it skipped under **Rows above the header**; change the number if it picked
  the wrong row.
- **Dates**: `2026-01-05`, `20260105`, month first (`01/05/2026`), day first (`05/01/2026`,
  `05.01.2026`, `05-01-26`), a two-digit year first (`26-01-05`), with or without a time after
  them, and written-out dates like `Jan 5, 2026`.
- **Amounts**: `1,234.56` or `1.234,56` (also `1 234,56`), with or without a currency symbol,
  and `-12.00`, `(12.00)`, `12.00-` or `12.00 DR` for money going out (`CR` for money coming in,
  and `S`/`H` in German exports). A `DR`/`CR` after the amount decides the direction even when
  the amount also has a sign (`-12.00 CR` is money coming in). With separate inflow and outflow
  columns, FlyBudget works out the sign.
- **Direction columns**: some banks (ING in the Netherlands, for one) write every amount as a
  positive number and say which way the money went in a column of its own: `Af`/`Bij`,
  `Debit`/`Credit` or `S`/`H`. Map that column as **Direction (in/out)** and FlyBudget signs
  the amounts from it. If your bank uses other words, FlyBudget asks: type the word for money
  going out under **Word for money out**, and any other word it doesn't know counts as money
  coming in.
- **Purchases written as positive amounts**: some exports, credit cards especially, write
  purchases as positive numbers and payments as negative ones. Tick **Flip amount signs** (shown
  when amounts come from one Amount column) and every amount gets the opposite sign; the preview
  shows the result. Amounts with a `DR`/`CR` after them keep their direction. FlyBudget never
  ticks it for you, but on a credit card or line of credit it points it out when most amounts in the file
  are positive. The account remembers it for the next file with the same columns.
- **Text**: UTF-8 (also UTF-16) and the older Windows encoding many banks still use, so names
  like _Müller_ or _Café_ come through intact. Files from Poland, Czechia, Hungary and nearby
  often use a Central European encoding instead: if letters like _ł_, _ś_ or _ő_ look wrong in
  the preview rows, choose **Central European (Windows-1250)** or **(ISO-8859-2)** under
  **Encoding**.
- Files up to 100,000 rows. Rows with an amount of zero are left out (the preview lists them).

FlyBudget works out from the file in which order dates are written, and whether amounts use a
decimal point or a decimal comma, and shows its choice under **Dates** and **Amounts**. (When
every date is written year first, like `2026-01-05`, or with the month in words, the order can't
matter, so there's no **Dates** to choose.) When the
file can't tell (every day in it is 12 or less, a two-digit year could come first or last, or
every amount looks like `1.234`), it asks you instead of guessing: a wrong guess would move
every transaction to another date, or make amounts a hundred times too big. Once you've answered
for an account, it remembers. Rows it can't read are left out, and the preview lists them.

## Excel workbooks

Excel files (`.xlsx`, also `.xlsm` and `.xltx`) import like CSV files: map the columns, then
preview. FlyBudget reads the file itself, in your browser or the app, without Excel.

- **Sheets**: when a workbook has more than one sheet with anything in it, a **Sheet** picker
  appears. FlyBudget opens the sheet with the columns you imported into this account last time,
  or else the first sheet that has a date and an amount column. Hidden sheets are left out.
- **Dates and amounts**: a cell Excel shows as a date is read as that day, and a number cell as
  that exact amount, so FlyBudget never has to ask how they're written. It only asks about dates
  and amounts typed as text, just like in a CSV file. A plain number in the date column (not
  shown as a date in Excel) isn't read as a date: the row is listed as skipped.
- **Formulas** are read by the value Excel saved with the file. Empty rows and columns are left
  out, so a table that starts a few columns or rows in still reads as one table.
- There's no **Separator** or **Encoding** to set. **Rows above the header** works as for CSV.
- Old `.xls` files and workbooks with a password can't be read: open them in Excel or
  LibreOffice, save a copy as `.xlsx` (without a password), and import that.

## CAMT.053 bank statements

CAMT.053 is the standard bank statement format in Europe (ISO 20022). Look for "CAMT", "XML" or
"ISO 20022" next to your bank's CSV download. It's the most reliable way to import: every amount
says whether it's money in or out, so there are no formats to work out.

- Only **booked** transactions are imported. Pending ones can still change or disappear, so
  they're left out (the preview says how many), and they'll come in with a later statement once
  they're booked.
- Each transaction is dated when the bank **booked** it, so it lands in the same month as on your
  statement.
- When one entry bundles several payments (a batch of transfers, say), FlyBudget lists each
  payment separately, as long as their amounts add up to the entry. If they don't, the entry is
  imported as one transaction, so the account balance is always right. (If you import an
  intraday CAMT.052 report and later the day's CAMT.053 statement, check the preview: a batch
  the report showed as one total is listed payment by payment in the statement, and can't be
  matched as a duplicate.)
- Importing a statement that overlaps an earlier one is safe: FlyBudget recognizes the
  transactions it already has by the bank's own reference for each one.
- A file with statements for more than one account asks which one belongs to the account you're
  importing into, and picks the one you imported into it before.
- FlyBudget remembers the account number (IBAN) of the last statement you imported into each
  account. If a statement is for a different account, the preview warns you, so a statement
  doesn't end up in the wrong account by mistake (you can still import it).
- A statement in another currency than the account's can't be imported into it: its amounts
  would mean something else. The preview offers to import it into one of your accounts in that
  currency instead.

If you switch an account from CSV files to CAMT.053 statements, check the first preview for
transactions you already have: the two formats describe the same transaction differently, so
FlyBudget can't always match them.

## Files with more than one currency

Some card statements list purchases in two currencies in one file, with a column saying which
currency each row is in (`Moneda`, `Currency`). Each account holds one currency, so an import
brings in only the rows in the account's currency, and then offers to import the others into
another account.

1. Import the file into one of the accounts, say the card's pesos account. FlyBudget recognizes
   the currency column by its header or its values and maps it as **Currency**.
2. Under **Currencies in this file**, each value in that column is listed with the currency
   FlyBudget read it as. It knows currency codes (`USD`), symbols (`€`, `US$`) and names in
   English and your device's language, however they're capitalized or accented. A word several
   currencies share, like _pesos_ or `$`, is read as the currency of the account you're importing
   into, or of an account in its [section](./accounts), when exactly one of them is in that
   currency. When FlyBudget can't tell, choose the currency yourself: it never guesses.
3. The preview lists only the rows in the account's currency, and says how many rows in other
   currencies aren't imported here. If there's nothing to import here (no rows in the account's
   currency, or you already have them all), it offers the other account right away.
4. After importing, FlyBudget offers **Import the USD rows into** one of your accounts in that
   currency, with the same file and settings. When the account you imported into is in a section
   with exactly one account of the same type in that currency (the card's dollars account), it's
   already picked. Choose **Preview** to see those rows and import them. If you'd rather not,
   choose **Done**.

FlyBudget remembers the currency column and what its values mean for each account, so the next
statement goes straight through. If every row of a file is in the account's currency, the import
works as usual. A row without a currency is left out (the preview lists it), and if neither the
account nor the budget has a currency yet, FlyBudget asks you to choose one in
**Settings → Currencies** before importing a file with rows in two currencies.

## Credit cards

Some banks export credit card purchases as positive numbers. If your purchases show up as money
coming in, map the column as **Outflow** instead of **Amount**. Every row is then treated as money
going out, so fix any refunds by hand after importing.
